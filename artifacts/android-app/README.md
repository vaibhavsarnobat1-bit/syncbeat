# SyncBeat Android app (Capacitor wrapper)

Real, installable APK that wraps the **live SyncBeat web deployment** in a full-screen
Android WebView (Capacitor 7, `server.url` remote-content mode). This replaces the old
fake `SyncBeat.apk` in `artifacts/website/public` (which was just a ZIP of a text
manifest and PNGs and could never install).

## Change the site URL & rebuild — ONE command

The URL has a single source of truth:

- `capacitor.config.ts` line ~20: `SITE_URL = process.env.SYNCBEAT_URL ?? "https://syncbeat-c7aj.onrender.com"`

After the Render service is renamed:

```bash
cd home/runner/workspace/artifacts/android-app
pnpm run build:apk -- https://<new-render-url>
```

(or edit the literal in `capacitor.config.ts`, then `pnpm run build:apk`).
The script runs `cap sync android` (bakes the URL into `assets/capacitor.config.json`
inside the APK), regenerates launcher icons, and runs Gradle `assembleRelease`.
Output: `dist/SyncBeat.apk`.

## Prerequisites (already set up on this machine)

- JDK 17 on PATH.
- Android SDK at `C:\vaibhav project\syncbeat-full-source\.android-sdk`
  (platform-tools, platforms;android-35, build-tools;35.0.0), installed via
  `.android-sdk/setup-sdk.sh` + `.android-sdk/sdk_install.py`.
- `android/local.properties` (generated by the build script) points Gradle at that SDK.
- Gradle itself is fetched by the wrapper (`android/gradlew.bat`).

## Signing

Current builds are **release builds signed with the debug certificate**
(`signingConfig signingConfigs.debug` in `app/build.gradle`) — fine for sideloading and
testing; NOT for Play Store. To switch: generate a keystore locally, put its path and
passwords in `android/keystore.properties` (add it to .gitignore — never commit
credentials), create a `signingConfigs.release` block reading that file, and change the
release buildType to use it.

## What is customized over the stock Capacitor template

- `MainActivity.java`: immersive full-screen, cutout handling, dark (#060708) window/WebView
  background (no white flash), inline media playback re-asserted, hardware/gesture back
  = WebView history first then `moveTaskToBack` (keeps audio + process alive for resume).
- `AndroidManifest.xml`: added `RECORD_AUDIO` + `MODIFY_AUDIO_SETTINGS` for SyncBeat voice
  rooms (Capacitor prompts at runtime when the page requests the mic).
- Adaptive launcher icons: brand mark on `#060708` (see `scripts/make-icons.mjs`, sources
  are `artifacts/website/public/brand-icon-512.png` / `brand-maskable-512.png`).
- `server.allowNavigation` includes `*.onrender.com`, YouTube and Google asset hosts.

## Known limitations

- Background audio with the *screen off* still stops (Chromium marks the page hidden);
  requires a foreground-service/media-session project to fix.
- Voice rooms need the user to accept the Android mic permission the first time.
- YouTube plays inline inside the WebView; the player's own fullscreen button relies on
  Chromium's WebView fullscreen support (usually works, varies by device).
